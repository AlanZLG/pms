## 1. 快速开始

### 1.1 系统简介

**Atlas** 是一款轻量级的团队项目管理 Web 应用,覆盖"看板与任务面板 / 进度跟踪与统计 / 项目与任务管理 / 团队协作与权限"四大核心模块,内置通知中心和完整的权限体系。

### 1.2 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端 | React 18 · Vite · TailwindCSS · Zustand · dnd-kit · Recharts |
| 后端 | Express 4 · better-sqlite3 · JWT · bcrypt · zod · multer · nodemailer |
| 数据库 | SQLite (本地文件存储 `data/app.db`) |
| 文件存储 | 本地磁盘 `data/uploads/`(任务附件) |

### 1.3 启动系统

```bash
# 安装依赖(首次运行)
npm install

# 同时启动前端与后端开发服务
npm run dev

# 或者分别启动
npm run server:dev     # 后端 API:http://localhost:3001
npm run client:dev     # 前端 Web:http://localhost:5173
```

打开浏览器访问 `http://localhost:5173` 即可使用。

## 2. 登录与账号

### 2.1 登录

1. 打开系统登录页,默认为"登录"标签。
2. 输入邮箱和密码。
3. 点击 **"登录系统"** 按钮进入系统。

### 2.2 注册新账号

1. 在登录页点击顶部 **"注 册"** 标签。
2. 填写昵称、邮箱、密码(密码明文传输,建议使用强密码)。
3. 点击 **"创建账号"** 完成注册。

新注册的账号默认角色为 **团队成员(member)**,由系统管理员在"团队"页面调整权限。

### 2.3 退出登录

点击右上角头像旁的 **退出图标**,即可安全退出当前会话。

## 4. 项目管理

### 4.1 进入项目列表

点击左侧导航栏 **"项目"** 进入项目列表页。

### 4.2 搜索与筛选

- **搜索框**:按项目名称或描述中的关键词过滤。
- **状态筛选**:切换标签可快速筛选"全部 / 进行中 / 已完成"。

### 4.3 创建新项目

1. 点击右上角 **"新建项目"** 按钮。
2. 在弹窗中**首先选择项目类型**(v1.8.5 必选,v1.9.0 扩为六选一按钮):
   - **运维项目**:登记运维台账,归集运维作业与工时
   - **运维增强**:基于现有系统的功能追加/改善开发,登记运维台账,结项后可合并到运维项目(见 4.8)
   - **开发项目 / 咨询项目 / 实施项目 / 产品迭代**:记录课题表
   - 未选择时无法提交,弹窗会给出红色提示
3. 继续填写(按弹窗从上到下的顺序):
   - **项目名称**(必填)
   - **项目描述**
   - **项目状态**:规划中 / 进行中 / 已完成 / 已归档
   - **截止日期**(与状态同排两列)
   - **项目模板**(可选):下拉按分类分组展示;选中后弹窗内显示模板预览卡(描述/分类/任务数/预算类别数/看板列数),自动带入模板任务/预算/看板列,并按模板分类预填同名项目类型
   - **项目负责人**(仅系统管理员可见):可从团队成员中指定负责人;不选则默认为创建者。指定后,该负责人会自动加入项目成员。
4. 提交后,新项目会出现在列表中。

> 💡 普通成员创建项目时不会看到"负责人"选项,默认自己为负责人。
> 💡 项目类型创建后可在项目详情页"编辑项目"中修改;类型决定台账入口名称——运维项目显示"运维台账",其余类型显示"课题表"。
> 💡 选择项目模板时会按模板分类自动预填同名项目类型(v1.8.7:五分类与五类型一一对应),可手动修改。

### 4.4 项目类型

项目类型(v1.8.5 引入,v1.8.7 扩为五类,v1.9.0 加入「运维增强」扩为六类)决定项目的记录用途、台账入口与模板联动,是项目体系的顶层分类。

**六类类型与作用**:

| 类型 | 台账入口 | 主要作用 |
| --- | --- | --- |
| 运维项目 | 运维台账 | 登记运维作业,归集作业内容与工时 |
| 运维增强 | 运维台账 | 基于现有系统的功能追加/改善开发,结项后可合并到运维项目(见 4.8) |
| 开发项目 | 课题表 | 记录开发课题 |
| 咨询项目 | 课题表 | 记录咨询课题 |
| 实施项目 | 课题表 | 记录实施交付课题 |
| 产品迭代 | 课题表 | 记录产品版本迭代课题 |

**选择流程**(三种途径,殊途同归):

1. **新建时手动选择**(推荐):新建项目弹窗第一步即五选一类型按钮(必选,未选择时无法提交)——见 4.3;
2. **由模板预填**:弹窗中选择项目模板后,自动按模板分类预填**同名**项目类型(五类模板分类与五类项目类型一一对应),可手动修改——见 18.1;
3. **事后补设**:历史项目创建时类型字段尚不存在,不显示徽章;可在项目详情页"编辑项目"中随时补设。

**类型的三个作用**:

- **决定台账入口名称**:项目详情页内嵌面板,运维项目/运维增强显示"运维台账",其余四类显示"课题表"(见 25.1);
- **类型徽章**:项目卡片与详情页标题展示六色徽章(完整颜色对照见 22.7 速查表);
- **模板联动**:创建模板时必选分类,选择模板即预填同名类型(见 18.1/18.3)。

**修改类型**:项目详情页"编辑项目"中修改(见 4.6),保存后台账入口名称立即切换。

### 4.5 项目卡片

每个项目卡片展示:

- **项目类型徽章**(五色区分,完整说明见 4.4;历史未设置类型的项目不显示)
- 项目状态徽章
- 项目名称与描述
- **进度条**(自动根据任务完成度计算)
- 项目成员头像堆叠
- 截止日期

点击卡片进入项目详情页。

### 4.6 编辑项目

在项目详情页点击 **"编辑项目"** 按钮,可修改项目信息(名称、描述、**项目类型**、状态、截止日期)。

> 💡 修改项目类型后,项目详情页内嵌台账面板的入口名称会立即随之切换:改为"运维项目"显示"运维台账",改为其他类型显示"课题表"。

### 4.7 删除项目与删除审批

删除项目的规则因角色而异:

- **系统管理员**:直接删除,项目进入回收站,可随时恢复。
- **项目负责人(创建者)**:点击删除后需提交**删除申请**,由管理员或项目核算人员审批:
  - 申请提交后,项目卡片会显示 **"删除审批中"** 徽章。
  - **批准**后项目移入回收站;**驳回**后项目恢复原状。
- **其他成员**:无法删除项目。

**驳回与通知**:审批人驳回时可填写驳回原因(选填,最多 200 字,带实时字数校验)。申请人会收到站内通知,项目卡片上也会显示 **"上次删除申请被驳回:〈原因〉"**;重新提交申请后,旧原因自动清除。申请被批准时,申请人同样会收到通知。

**审批入口**:管理员与项目核算人员在 **"回收站"** 页面顶部可看到 **"待审批删除申请"** 区块,直接批准或驳回,无需到项目卡片逐个处理。

### 4.8 结项合并到运维项目(v1.9.0)

「运维增强」项目(基于现有系统的功能追加/改善开发)通常生命周期短暂,结项后其作业记录与工时应归集到主体运维项目名下。系统提供**一键合并**能力:

**适用条件**:

- 源项目类型为**运维增强**;
- 源项目尚未合并过;
- 目标项目类型为**运维项目**且未合并到其他项目;
- 操作人为系统管理员或项目负责人。

**操作流程**:

1. 进入运维增强项目详情页,点击工具栏 **"合并到运维项目"** 按钮;
2. 在弹窗中选择目标运维项目(仅列出合法的运维项目);
3. 确认合并。系统在**一个事务内**完成:本项目名下全部台账/课题记录批量转绑到目标运维项目(工时随之归集到目标项目统计)→ 本项目标记为「已合并」。

**合并后的表现**:

- 项目卡片与详情页标题显示青色 **"已合并 → 目标项目名"** 徽章;
- 目标运维项目的台账/课题列表中可查到全部转绑记录;
- 合并操作不可撤销;合并前请确认源项目无进行中的作业;
- 项目任务/预算等其余内容保留在原项目作过程留痕,不随合并迁移。

> 💡 合并逻辑同样受后端强校验保护:非运维增强项目、重复合并、目标非法均会返回明确错误提示。

## 5. 项目详情 · 甘特图、看板与任务

进入项目后,**默认显示甘特图视图**,可随时通过工具栏切换到看板或列表视图。

### 5.1 页面结构

- **顶部区域**:项目名称、状态徽章、描述、进度条、任务数量
- **操作按钮**:导出任务(CSV)、导出进度(Excel)、编辑项目、新建任务
- **工具栏**:搜索框 + 视图切换(列表/看板/**甘特图**) + 批量操作入口(列表视图)
- **主区域**:任务展示区

### 5.2 甘特图视图

以时间线方式展示项目任务,是进入项目后的默认视图。

#### 5.2.1 甘特图核心概念

| 元素 | 说明 |
| --- | --- |
| 任务条 | 水平长条表示任务,长度对应起止日期跨度,深色填充表示已完成进度,右侧常显进度百分比数值 |
| 实际条 | 填写了实际开始/实际截止日期后,任务条下方显示绿色实心条表示实际执行区间;同时任务条变为虚线半透明样式,表示"计划" |

> 💡 **日期口径**:甘特图按**闭区间**绘制——计划/实际日期所填的**当天与截止当天都计入**色块(如同一天填开始与截止,色块占 1 格;间隔 3 天的任务,色块占 4 格)。即"9 月 1 日 ~ 9 月 3 日"表示 9 月 1、2、3 三天全在任务期内。
| 依赖线 | 任务间的贝塞尔曲线箭头,表示前后依赖关系(FS/SS/FF/SF) |
| 关键路径 | 红色边框标注的任务,决定项目最短工期,拖动物会影响整体进度 |
| 泳道 | 按负责人分组的行,可折叠/展开 |
| 日期轴 | 顶部显示日期刻度,支持日/周/月三级缩放 |

#### 5.2.2 点击任务名称快速编辑

点击甘特图 **左侧列表中的任务名称**,弹出快速编辑面板,无需打开任务详情抽屉:

| 字段 | 说明 |
| --- | --- |
| 计划开始 / 计划截止 | 决定甘特图色块的位置与长度 |
| 实际开始 / 实际截止 | 选填。填写后甘特图显示计划/实际对比:计划条变虚线半透明,绿色实心条表示实际区间;只填实际开始时,绿条从实际开始延伸到今天(表示进行中) |
| 进度 | 0-100 滑块,保存后色块内进度填充与右侧百分比数值同步更新 |

面板底部提供 **"查看完整详情"** 入口,可跳转到任务详情抽屉编辑其他字段。

#### 5.2.3 拖拽调整进度

1. 将鼠标悬停到任务条 **右侧边缘**
2. 光标变为 `col-resize` 样式
3. 按住鼠标 **左右拖动**,实时调整完成百分比
4. 松开鼠标后进度自动保存

#### 5.2.4 拖拽调整任务时间

1. 将鼠标悬停到任务条 **主体** 区域
2. 按住鼠标拖动,改变开始日期和截止日期
3. 拖拽时自动吸附到最近的时间刻度(对齐精度)

#### 5.2.5 依赖关系

- **FS**(Finish-to-Start):前序完成后,后序才能开始
- **SS**(Start-to-Start):前序开始后,后序才能开始
- **FF**(Finish-to-Finish):前序完成后,后序才能完成
- **SF**(Start-to-Finish):前序开始后,后序才能完成

点击任务条左侧的 **依赖手柄** 并拖到目标任务上即可建立依赖关系。

#### 5.2.6 键盘快捷键(甘特图)

| 操作 | 快捷键 |
| --- | --- |
| 放大时间线 | `+` 或 `=` |
| 缩小时间线 | `-` |
| 回到今天 | `D` |
| 切换负责人分组 | `G` |
| 取消选择/依赖连接 | `Esc` |
| 搜索任务 | `/` 或点击搜索框 |

#### 5.2.7 过滤与分组

- **搜索**:工具栏搜索框输入关键词,按任务标题/描述过滤
- **负责人分组**:切换泳道模式,按负责人折叠/展开分组
- **筛选**:通过负责人、状态、标签等维度筛选任务

看板将任务按状态分成四列:

| 列名 | 说明 |
| --- | --- |
| 待办 | 尚未开始的任务 |
| 进行中 | 正在执行的任务 |
| 审核中 | 等待审核或验收 |
| 已完成 | 已完成的任务 |

#### 5.2.1 拖拽更新状态

直接用鼠标按住任务卡片,拖拽到目标列,松开即可完成状态更新,系统会自动同步到后端。

> 💡 **小技巧**:鼠标移动超过 5px 才会触发拖拽,避免误操作。

#### 5.2.2 在指定列新建任务

点击某列标题旁的 **"+"** 按钮,会自动将新建任务的预设状态设为该列对应的状态。

#### 5.2.3 看板卡片信息

每张任务卡片显示:
- 任务标题
- 标签 (如有)
- 优先级徽章

### 5.3 列表视图

- 可按状态(全部/待办/进行中/审核中/已完成)快速筛选

#### 5.3.1 批量操作

列表视图支持多选批量操作,大幅提升管理效率:

1. 点击工具栏 **"批量操作"** 按钮进入多选模式。
2. 勾选需要操作的任务(或点击表头全选)。
3. 在底部批量工具栏选择操作:

   - **批量删除**:确认后删除所有选中任务

### 5.4 新建任务

1. 点击 **"新建任务"** 按钮。
2. 若已有任务模板,对话框顶部会显示 **"从模板创建"** 区域:

   - 也可点击模板旁的删除图标移除不再需要的模板
3. 填写任务信息:
   - **任务标题**(必填,最多 120 字符,超长会实时提示)
   - **任务描述**
   - **状态**:待办 / 进行中 / 审核中 / 已完成
   - **优先级**:低 / 中 / 高 / 紧急

4. 提交后,任务会出现在看板、列表或甘特图中。

> 💡 可在对话框底部点击 **"保存为模板"**,将当前任务配置保存为模板,下次创建任务时快速复用。

### 5.5 编辑与删除任务

- 点击 **垃圾桶图标** 编辑

## 7. 任务模板管理

任务模板用于预定义任务的标准配置(标题、描述、优先级、标签),适合重复性工作场景(如 Bug 修复、需求评审、发布流程等),可大幅减少重复输入。

### 7.1 创建模板

有两种方式创建模板:

**方式一:从新建任务对话框保存**
1. 点击"新建任务"打开对话框。
2. 在对话框底部点击 **"保存为模板,下次快速创建"**。
3. 输入模板名称(必填)。
4. 点击 **"保存"** 按钮,当前填写的标题、描述、优先级、标签会被保存为模板。

**方式二:直接填写后保存**
1. 在新建任务对话框中填写所需字段。
2. 点击底部"保存为模板"区域。
3. 输入模板名称并保存。

### 7.2 使用模板创建任务

1. 点击"新建任务"打开对话框。
2. 若已有模板,对话框顶部会显示 **"从模板创建"** 区域。
3. 从下拉菜单选择模板,系统自动填充:
   - 任务标题
   - 任务描述
   - 优先级
   - 标签
4. 可在填充基础上继续修改,补充负责人、截止日期等信息。
5. 提交保存即可。

### 7.3 删除模板

1. 在新建任务对话框的"从模板创建"区域选择要删除的模板。
2. 点击模板下拉框旁的 **垃圾桶图标**。
3. 确认后模板被删除(已用该模板创建的任务不受影响)。

> 💡 模板对所有用户共享,任何登录用户都可创建和使用模板。

## 8. 预算与支出管理

预算管理帮助项目团队规划和控制项目成本,支持预算审批流程和支出登记。

### 8.1 预算面板入口

在项目详情页点击 **"预算"** 标签页或滚动到预算区域,即可查看和管理项目预算。

### 8.2 预算类别

系统支持五种预算类别:

| 类别 | 英文 | 说明 |
| --- | --- | --- |
| 人工成本 | labor | 团队成员薪酬成本 |
| 外包费用 | outsource | 外包人员费用 |
| 硬件采购 | hardware | 设备、服务器等 |
| 软件采购 | software | 软件 licenses 等 |
| 其他支出 | other | 杂项支出 |

### 8.3 创建预算

1. 在预算面板点击 **"添加预算"** 按钮。
2. 在弹窗中填写:
   - **预算类别**(必填):从五种类别中选择
   - **预算金额**(必填):必须大于 0,单位 RMB(¥)
   - **备注说明**:可选,描述预算用途
3. 提交后,新建预算的状态为 **"待审批"**。

> ⚠️ **权限说明**:项目成员可创建预算,但需管理员或项目核算审批后才能生效。

### 8.4 预算审批

**仅系统管理员和项目核算人员可审批预算**:

1. 进入预算面板,找到状态为"待审批"的预算项。
2. 点击 **"审批"** 按钮:
   - **批准**:点击"批准"确认,预算状态变为"已批准"
   - **驳回**:点击"驳回",填写驳回原因(可选),预算状态变为"已驳回"
3. 已批准的预算会显示在预算汇总中,可用于支出登记。

> ⚠️ 已审批的预算无法修改或删除。

### 8.5 查看预算汇总

预算面板顶部显示预算汇总:
- **总预算**:所有已批准预算的总额
- **已使用**:已登记支出的总额
- **剩余预算**:总预算 - 已使用
- 各类别预算占比分布图

### 8.6 登记支出

1. 在预算面板点击 **"登记支出"** 按钮。
2. 填写支出信息:
   - **关联预算**:选择对应的已批准预算项(可选)
   - **支出类别**:与预算类别对应
   - **支出金额**(必填)
   - **支出日期**(必填)
   - **备注说明**:可选
3. 提交后,支出实时计入项目成本统计。

### 8.7 成本统计

系统会自动汇总项目成本数据:
- 按类别展示预算 vs 支出对比
- 按成员展示工时成本(基于时薪计算)
- 剩余预算预警(支出接近预算时高亮提醒)

> 💡 成本数据在"统计"页面的项目成本报表中也可查看。

## 9. 工时管理

工时管理用于记录和追踪项目中每个任务的工时投入。

### 9.1 任务工时登记

在任务详情抽屉的 **"工时"** 区域可以登记工时:

1. 进入任务详情,滚动到"工时"区域。
2. 点击 **"添加工时记录"** 按钮。
3. 填写:
   - **日期**:工时发生的日期
   - **计划工时**:本次预计耗时(小时,选填;填写后计入报表的"登记计划工时")
   - **内部实际工时**:实际投入的小时数
   - **计费工时**:可向客户计费的小时数(选填)
   - **备注**:可选说明
4. 提交后,工时记录显示在列表中(含计划/内部/计费三列数值)。

**登记时机**:工时登记**不限任务状态**,待办/进行中/审核中/已完成的任务均可登记:

| 任务状态 | 典型场景 | 说明 |
|----------|----------|------|
| 进行中 | 每日记录当日投入 | **最常用的场景**。报表据此实时反映消耗——计划 40h 的任务已登记 30h 且未完成,工时偏差立即预警,无需等任务做完 |
| 审核中 | 补录收尾阶段投入 | 修正统计 |
| 待办 | 前期调研/准备投入、历史补录 | 较少用 |
| 已完成 | 收尾补录 | 结清尾差 |

> 💡 工时登记记录的是"投入"而非"结算",与 Jira worklog、飞书项目工时的规则一致。若只在任务完成后才登记,趋势图、偏差分析、消耗进度将全部失去实时预警意义,因此**建议进行中的任务按日登记**。

> 💡 工时报表顶部的"任务计划工时"来自任务设置的计划工时(`tasks.planned_hours`),而这里的"计划工时"是每次登记时填写的,两者是独立口径。

#### 9.1.1 相关入口:任务进度与日期的快速编辑(甘特图)

任务**进度**与工时登记是两个独立口径:进度反映"完成程度"(0-100%,驱动项目进度计算),工时登记记录"时间投入"(小时数)。调整任务进度不必进入任务详情——在项目详情的 **甘特图** 中点击左侧任务名称,弹出快速编辑面板,可一次修改 5 个字段:

| 字段 | 作用 |
|------|------|
| 计划开始 / 计划截止 | 决定甘特图色块的位置与长度 |
| 实际开始 / 实际截止 | 选填;填写后甘特图显示计划/实际对比——计划条变虚线半透明,绿色实心条表示实际区间(只填实际开始时延伸到今天) |
| 进度 | 0-100 滑块,保存后色块填充与右侧百分比数值同步,并与任务详情进度同源 |

> 💡 面板底部"查看完整详情"可跳转任务详情抽屉;甘特图交互细节见 5.2.2 节。

### 9.2 工时报表

点击导航栏 **"工时报表"** 进入工时统计页面,顶部四个核心卡片:

| 卡片 | 口径 | 来源 |
|------|------|------|
| 任务计划工时 | 项目内任务的计划工时设置合计 | 任务(02_项目模块) |
| 登记计划工时 | 历次工时登记中填写的计划工时合计 | 工时登记记录 |
| 内部实际工时 | 历次登记的内部实际工时合计 | 工时登记记录 |
| 工时偏差 | 内部实际 − 任务计划,配偏差率 | 前两者相减 |

**筛选**:项目 / 人员 / 日期范围均为服务端真实过滤。**默认值**:期间为当月 1 日至当月最后一天;项目默认选中当前用户负责的第一个项目(若未负责任何项目则为"全部项目",手动切换后不再自动回填)。**人员下拉随项目联动**:选中具体项目时先列出该项目成员(含项目负责人),再自动补齐**历史参与人**——在该项目/期间内有登记记录或负责任务、但已不在成员列表的人(带"历史参与"标注),保证每个工时数字都能找到归属人;选"全部项目"时显示所有人员。同名人员自动追加邮箱前缀区分,切换项目后已选人员若不在新列表中会自动回退为"全部人员"。按人员筛选时,卡片下会提示"另有 X 小时任务未指派负责人";筛选结果同时作用于任务计划工时(按任务负责人归集)。

**常见疑问:选了某个人员后,工数全部变成 0?**

工数为 0 通常不是错误,而是**筛选组合的结果**:四个筛选条件(项目/人员/期间)同时生效。例如页面默认选中了某个具体项目,若所选人员在该项目、该期间内没有登记记录,所有卡片、趋势图、明细都会显示为 0/空。此时可:

1. 先把 **项目** 切回"全部项目"再看该人员——若仍为 0,说明其在该期间确实没有任何登记;
2. 检查 **日期范围** 是否只覆盖了当月,历史登记需要放宽期间;
3. 图表与明细的空态文案为"当前筛选条件下暂无记录,可调整项目/人员/日期范围",按提示调整即可。

> 💡 切换筛选后页面只采用**最后一次**请求的结果(防快速连点时旧数据残留);若数据加载失败,页面顶部会显示红色错误提示"工时数据加载失败",**调整任意筛选条件即自动重试**,无需手动刷新。

**工时趋势图**(按日,时间轴始终与顶部期间筛选一致):
- 蓝色柱 = 登记计划工时(每日登记的计划工时)
- 绿色柱 = 登记实际工时(每日登记的实际工时)
- 黄色实线 = **计划累计**(任务计划基线逐日累计,右轴):任务计划工时按其起止日期区间按天均摊后累计;仅区间 ≤60 天的任务参与,超长或未设日期的任务不参与,图下方会提示未计入的小时数;跨期任务只累计所选期间内的部分
- 青色实线 = **实际累计**(每日登记实际逐日累计,右轴)
- 读图方法:两根累计线构成 S 曲线对比——**青线在黄线上方**表示实际消耗快于计划(可能提前完工或超支),**黄线在青线上方**表示进度落后于计划;两线终点差 = 期间内计划与实际的总量差

**工时记录明细**:按筛选条件列出每条登记记录,选"全部人员"时显示项目内所有人员的记录。

- **列构成**:日期 / 项目 / 任务 / 登记人 / 计划工时 / 内部工时 / 计费工数 / 偏差 / 说明
- **表头排序**:除"说明"列外,其余 **8 列均可点击表头排序**——表头旁显示排序图标(未激活为上下双箭头 ⇅,升序 ↑,降序 ↓),当前排序列高亮显示
- **排序方向**:文本列(项目/任务/登记人)首次点击按**升序**,数值列(计划工时/内部工时/计费工数/偏差)首次点击按**降序**(便于先看最大值);再次点击在同一列的升/降序间切换
- **默认顺序**:按日期降序(最新登记排在最前)
- **与筛选的关系**:排序只改变明细行的展示顺序,不影响顶部统计卡片、趋势图与人员-项目矩阵的数值;调整筛选条件后明细按新结果重新加载,已选的排序方式保持不变

**人员-项目工时矩阵**:行=人员、列=项目,展示计划/内部/计费三维工时。矩阵与顶部**项目筛选联动**——选"全部项目"时展示期间内所有项目列;选中具体项目时矩阵只保留该项目一列(即该项目的人员工时汇总),与卡片、趋势图口径一致。

**人员成本明细**:按项目分组列出每位成员的类型(内部/外包)、单价、总工数与总成本。**表头可排序**:5 个列(人员/类型/单价/总工数/总成本)均可点击排序,交互与工时记录明细一致——文本列(人员)首次点击升序、数值列(单价/总工数/总成本)首次点击降序、"类型"列按内部在前排序;默认按**总工数**降序(工时最多的成员排最前)。排序在多个项目表之间全局生效,便于跨项目按同一口径对比。

> 💡 **总成本 = 时薪 × 总工数**:成员时薪取"团队"页成员设置(未设置时回退其人员类别的默认时薪,再未设置则按 0 计)。若所有成员的成本都显示 0,说明尚未配置时薪——请在"团队"页编辑成员设置时薪,或创建人员类别并设置默认时薪后绑定成员。

**权限**:报表主数据对全部登录用户开放,且仅统计自己参与的项目;人员-项目矩阵、项目成本、分类统计等汇总区块仅财务/管理员可见,普通用户会看到"仅财务与管理员可见"提示而非空数据。

**长列表滚动布局**:项目与人员较多时,各区块在卡片内部滚动,不会把页面撑得过长:

| 区块 | 滚动方式 |
|------|----------|
| 人员-项目工时矩阵 | 双向滚动(纵向+横向,高度上限 560px);表头吸顶、人员列吸左、左上角双向固定、合计行吸底,滚动中行头/列头始终可见 |
| 工时记录明细 | 纵向滚动(高度上限 560px) |
| 人员成本明细 / 项目成本汇总 / 成本分类统计 | 纵向滚动 |
| 人员工时统计 | 列表内纵向滚动,与左侧工时趋势图等高对齐(约 380px) |

> 💡 滚动条只在内容超出可视高度时出现——项目/人员较少看不到滚动条属正常现象。

### 9.3 成员时薪设置

**仅系统管理员可设置成员时薪**:

1. 进入 **"团队"** 页面。
2. 找到目标成员,点击编辑按钮。
3. 设置:
   - **是否外包**:标记为外包人员
   - **时薪**:每小时费率(RMB)
   - **成本中心**:成本归属部门
   - **人员类别**:从预设类别中选择(可在团队页面管理类别)
4. 保存后,工时成本会自动计算。

**时薪取值优先级(回退链)**:成员成本按以下顺序取时薪,前一级未设置则自动回退:

1. **个人时薪**:团队页为该成员单独设置
2. **类别时薪**:成员所绑定人员类别的默认时薪
3. **项目角色默认价**:在该项目中担任**项目负责人** ¥200/小时、外包人员 ¥125/小时、其他成员 ¥150/小时(系统内置默认价)
4. 以上均无时按 0 计

> 💡 同一成员在不同项目角色可能不同(如 A 项目当负责人、B 项目当成员),系统按**每个项目内的实际角色**动态取价,而非套用固定类别价。团队页成员卡片上未单独设置时薪的成员会提示"默认价(负责人项目内 ¥200)"。

### 9.4 人员类别管理

在团队页面可以管理人员类别:
- 创建自定义类别(如"前端开发"、"后端开发"、"测试"等)
- 设置类别默认时薪
- 标记类别是否为外包

## 10. 进度跟踪与统计

点击导航栏 **"统计"** 进入数据统计页面。

- **总任务**(紫色)

帮助管理员合理分配任务,识别过载或闲置成员。

> 💡 **口径与滚动**:统计窗口内**有动态**(新建或更新,按任务更新时间过滤)的任务;成员较多时图表区域可纵向滚动,柱条高度自适应人数、保持清晰可读。

### 10.5 项目成本报表

成本报表展示项目核算数据:
- **预算汇总**:各项目的总预算、已使用、剩余

## 11. 团队协作与权限

点击导航栏 **"团队"** 进入团队管理页面。

### 11.1 角色体系

系统定义了五种角色:

| 角色 | 权限说明 |
| --- | --- |
| **系统管理员** (admin) | 最高权限,可修改所有成员角色、审批预算与项目删除申请、管理所有项目 |
| **项目核算人员** (finance) | 审批预算与项目删除申请、查看成本数据、管理成员时薪 |
| **项目负责人** (owner) | 管理自己负责的项目,创建与分配任务,提交项目删除申请 |
| **团队成员** (member) | 参与项目,分配和执行任务 |
| **访客** (guest) | 仅查看,不可编辑或创建任务 |

> 💡 除以上内置角色外,管理员还可在"角色管理"页面创建自定义角色并配置细粒度权限(共 40 项,按 9 大分类分组)。

### 11.2 页面可见性(权限分级)

"团队"页面的可见性由 **team.view** 权限点控制(系统管理员/项目核算/项目负责人默认具备,自定义角色可在角色管理中勾选):

| 身份 | 侧边栏"团队"入口 | 直访 `/team` |
| --- | --- | --- |
| 系统管理员 / 项目核算 / 项目负责人 | 显示 | 完整通讯录(邮箱+任务统计) |
| 团队成员 / 访客(及未勾选 team.view 的自定义角色) | 隐藏 | 提示"仅管理员、财务与项目负责人可见" |

> 💡 成员/访客虽然没有团队页,但**协作不受影响**:创建或编辑任务时,负责人下拉仍可正常选择所有人;如需指派任务,在任务创建时选择负责人即可。

### 11.3 成员信息

**有 team.view 权限的用户**,每张成员卡片展示:
- 头像与昵称
- 邮箱
- 负责的任务数
- 进行中的任务数
- 当前角色
- 时薪(仅管理员/项目核算可见)

成员批量导入、修改角色、成员成本等管理操作也仅对该类用户开放(详见下文各小节)。

### 11.4 修改角色

**仅系统管理员可修改角色**:

### 11.5 成员成本管理

3. 保存后,工时成本会自动计算。

### 11.6 人员类别管理

- 标记类别是否为外包

## 13. 数据导出

系统支持将项目与任务数据导出为 CSV 文件,方便数据分析、汇报与备份。

### 13.1 导出项目列表

1. 进入 **"项目"** 页面。
2. 点击右上角 **"导出 CSV"** 按钮。

## 14. 回收站(任务与项目)

回收站存放已删除的任务和项目,支持恢复;任务还支持彻底删除。

### 14.1 进入回收站

点击左侧导航栏 **"回收站"** 进入回收站页面。

### 14.2 查看已删除任务

回收站显示所有已删除的任务,包括:
- 任务标题、描述
- 原所属项目
- 删除时间
- 原负责人

支持搜索过滤,快速定位目标任务。

### 14.3 恢复任务

1. 在回收站中找到目标任务。
2. 点击 **"恢复"** 按钮。
3. 确认后,任务将恢复到原项目中,状态和内容保持不变。

> 💡 恢复后的任务会出现在原项目的看板/列表/甘特图中,其他用户可见。

### 14.4 彻底删除

1. 在回收站中找到目标任务。
2. 点击 **"彻底删除"** 按钮。
3. 确认后,任务将被永久删除,无法恢复。

> ⚠️ 彻底删除不可恢复,请谨慎操作。

### 14.5 清空回收站

目前回收站中的条目需要逐条处理,暂不支持一键清空。

### 14.6 恢复项目

被删除的项目同样存放在回收站中(项目区域位于任务列表下方):

1. 在回收站页面找到目标项目。
2. 点击 **"恢复"** 按钮。
3. 确认后,项目及其全部任务将完整恢复。

> 💡 项目没有"彻底删除"操作,删除的项目永远可以在回收站恢复。

### 14.7 处理删除审批申请

管理员与项目核算人员进入回收站后,页面顶部显示 **"待审批删除申请"** 区块,列出每个待审批项目的名称、申请人与申请时间:

1. 点击 **"批准删除"** → 项目移入回收站,申请人收到批准通知。
2. 点击 **"驳回"** → 项目恢复原状,申请人收到驳回通知(含驳回原因)。

> 💡 该区块仅对管理员/项目核算人员显示;队列清空时自动隐藏。普通用户提交删除申请后,可在项目卡片上看到"删除审批中"徽章并等待处理。

## 23. 常见问题 FAQ

### Q1: 如何重置所有数据?

删除项目根目录下的 `data/app.db` 文件(及 `data/uploads/` 目录),重启系统即可自动重建演示数据。

```bash
rm -f data/app.db
rm -rf data/uploads
npm run dev
```

### Q2: 忘记密码怎么办?

当前版本密码使用 bcrypt 加密存储,无法直接找回。请联系系统管理员:

```bash
# 使用 Node.js 快速重置密码
node -e "
const bcrypt = require('bcrypt');
const hash = bcrypt.hashSync('新密码', 10);
console.log('新密码哈希:', hash);
"
```

然后通过 SQLite 工具更新对应记录的 `password_hash` 字段。

### Q3: 如何添加新的项目成员?

当前版本的成员管理通过"团队"页面 + 项目详情中负责人分配完成:
1. 管理员在登录页注册新用户
2. 在"团队"页面将其角色设置为"团队成员"
3. 在项目详情中创建任务时,将新成员指定为负责人

### Q4: 看板拖拽没有反应怎么办?

- 确认当前账号角色不是"访客"(guest),访客无编辑权限
- 检查是否存在网络延迟,可刷新页面后重试
- 若使用触摸板/触屏,确保 PointerSensor 已正确触发(需要移动 > 5px)

### Q5: 如何导出数据?

系统内置 CSV 导出功能(详见第 13 章):

- **项目列表导出**:在"项目"页点击"导出 CSV"
- **任务列表导出**:在项目详情页点击"导出任务"

如需导出全量原始数据为 JSON,可使用脚本:

```bash
node -e "
const Database = require('better-sqlite3');
const db = new Database('data/app.db');
const tables = ['users','projects','project_members','tasks','comments','subtasks','notifications','templates','attachments'];
const data = {};
tables.forEach(t => data[t] = db.prepare('SELECT * FROM ' + t).all());
require('fs').writeFileSync('export.json', JSON.stringify(data, null, 2));
console.log('已导出到 export.json');
"
```

### Q6: 通知数据存储在哪里?

通知存储在 SQLite 的 `notifications` 表中。系统会在以下场景自动生成通知:
- 任务被分配(assign 类型)
- 任务状态变更(status 类型)
- 收到评论或 @提及(comment 类型)
- 系统提示(system 类型)
- 任务完成(同时触发邮件通知,需配置 SMTP)

### Q7: 邮件通知不生效怎么办?

邮件通知需要配置 SMTP 服务器。请检查:

1. 项目根目录是否创建了 `.env` 文件(可参考 `.env.example`)
2. 是否填写了 `SMTP_HOST`、`SMTP_USER`、`SMTP_PASS` 三个必填项
3. 密码是否为邮箱的 **SMTP 授权码**(非登录密码,QQ/163 等邮箱需单独开启)
4. 端口是否正确:SSL 通常 465,TLS 通常 587
5. 查看后端控制台日志,是否有 `[mail]` 相关错误输出

未配置 SMTP 时系统会打印 `[mail] SMTP 未配置,跳过邮件发送` 警告,属正常行为。

### Q8: 附件上传失败怎么办?

- 单个文件大小不能超过 **20MB**
- 检查 `data/uploads/` 目录是否存在且有写入权限(系统会自动创建)
- 查看浏览器控制台与后端日志的错误信息
- 若附件丢失(文件被手动删除),下载时会提示"文件已丢失"

### Q9: 如何调整任务的完成进度?

在甘特图视图中,有两种方式调整任务进度:

1. **拖拽调整**:将鼠标悬停到任务条右侧边缘,出现拖拽手柄后左右拖动,实时调整完成百分比
2. **直接编辑**:在任务详情抽屉中直接修改进度数值

进度保存后,项目的整体进度会自动重新计算。

### Q10: 甘特图中关键路径如何判断?

系统使用 **CPM(关键路径法)** 算法自动计算:
- 找出所有从开始到结束的最长路径
- 路径上的任务即为关键任务(红色边框标注)
- 关键路径上任何任务的延迟都会直接导致项目延期
- 非关键任务有一定的浮动空间,可在浮动范围内调整而不影响项目工期

### Q11: 新建项目时为什么必须选择项目类型?(v1.8.5)

项目类型决定项目的记录用途与台账入口名称:运维项目登记运维台账,开发/咨询/实施/产品迭代项目记录课题表。因此新建时必须五选一,未选择时"创建"按钮不会提交。历史项目未设置类型不受影响(不显示类型徽章),可在项目详情页"编辑项目"中补设或修改。

## 25. 运维台账/课题表

左侧导航 **"运维台账/课题表"** 进入独立页面，按项目隔离管理记录并支持 Excel 批量导入/导出与自定义扩展字段。同一套表双用途：**运维项目**登记运维台账，**开发实施项目**记录课题进展（v1.8.4）。

### 25.1 项目 Tab 与数据隔离

页面顶部的项目 Tab 决定数据范围：**全部台账**（跨项目全量视图，列表会多出"项目"列）/ 各项目 Tab。打开页面时默认选中第一个项目；切换 Tab 时筛选条件自动重置；新增记录自动归属当前 Tab 的项目。

> **台账必须关联项目（v1.8.3）**：所有运维作业（含内部作业、内部学习等）都必须归属到某个项目名下，作业内容与工时统一归集到项目进行统计。系统已移除「未关联」视图，新建与导入都必须选择所属项目。

> **按项目类型动态命名（v1.8.5）**：项目详情页内嵌面板的入口与标题按项目类型显示——**运维项目**显示「运维台账」，**开发/咨询/实施项目**显示「课题表」；独立页面与导航统一叫「运维台账/课题表」。

### 25.2 筛选与排序

- **筛选**：搜索框（问题/描述/原因/方案/系统/提出人关键词，防抖 350ms）+「筛选」面板（分类/状态/系统/部门/日期区间）
- **排序**：点击表头列标题即可排序，再次点击切换升/降序。除 **问题、扩展字段、项目、操作** 外，其余 10 列均支持排序：

| 可排序列 | 首次点击方向 | 排序规则 |
| --- | --- | --- |
| 日期 | 降序（新的在前） | 按台账日期 |
| 分类 | 升序 | 按名称 |
| 状态 | 升序 | 按业务顺序：待处理 → 处理中 → 已完成 → 已关闭 |
| 系统 | 升序 | 按名称 |
| 部门 | 升序 | 按名称 |
| 提出人 | 升序 | 按名称 |
| 记录人 | 升序 | 按名称 |
| 完成日 | 降序 | 按完成日 |
| 工时 | 降序（多的在前） | 按工时数 |
| 登记日期 | 降序（新的在前） | 按录入系统时间 |

> 💡 首次点击方向按列语义预设：文本列（分类/系统/部门/提出人/记录人/状态）升序便于按名称查找；日期与数值列（日期/完成日/工时/登记日期）降序便于看最新、最多。当前排序列以蓝色高亮并显示 ↑/↓ 箭头，未排序列显示双向箭头。**导出 Excel 与列表使用相同排序**，导出文件行序与页面所见一致。

**日期列说明**：第一列 **"日期"** 是问题发生的日期（可编辑）；最后的数据列 **"登记日期"** 是记录录入系统的时间（系统自动记录，不可修改，悬停可查看精确到时分秒的登记时间）。两者独立：补录历史问题时发生日期填过去，登记日期仍是当天。

### 25.3 新增 / 编辑 / 删除 / 只读详情

点击「新增记录」或行尾编辑按钮，必填项为 **问题** 与 **所属项目**（v1.8.3 起表单下拉仅列可选项目，无「不关联」选项；未选项目无法保存，接口同样强制拦截）；分类/系统/部门支持输入建议（自动收集历史值）。**扩展字段**可自定义任意键值对（如客户名称、影响程度），导入导出 Excel 时自动识别为独立列。

**必填规则（v1.8.2）**：状态为**「已完成」**时，「详细描述 / 原因 / 解决方案」三项必填（表单中带 * 标记，未填无法保存，接口与导入同口径拦截）；「待处理 / 处理中」状态不强制，可先登记后补齐——支持把问题先记下来、解决后再补全经验字段的工作流。

**只读详情**：没有台账编辑权限的用户点击记录时，弹窗以只读模式展示全部字段（表单置灰、隐藏 AI 分析与保存按钮），便于普通成员查看完整台账内容；有编辑权限的用户照常进入编辑模式。

### 25.4 Excel 导入 / 导出 / 模板

- **模板**：下载标准 13 列模板（分类/状态/提出人/系统/部门/日期/记录人/问题/完成日/工时/详细描述/原因/解决方案）
- **导入**：自动识别表头行；状态支持中英文（done/processing 等自动映射，无法识别回退为"待处理"）；日期支持 `2026/01/02`、`2026-01-02`、Excel 序列号等格式；单行失败不影响其他行。**必须先选中具体项目再导入**（v1.8.3）：在「全部台账」视图下点击导入会提示先选择项目 Tab；接口层面未指定项目同样拒绝
- **导入查重（v1.8.1）**：选择文件后系统**先预检**（不写入）——「项目 + 作业日期 + 问题」与已有台账相同、或与同一文件内前面的行相同时判定为重复：**无重复**直接导入；**发现重复**时弹出确认窗口，由你选择 **「跳过重复，导入新记录」（推荐）/「全部照导」/「取消导入」**
- **预检确认窗口的三类提示**（发现重复时展示，帮助你在导入前发现文件问题）：
  1. **重复明细**——逐行列出行号 + 问题 + 日期，明确哪些行会被跳过
  2. **经验字段提醒（v1.8.2）**——「已完成」但缺少详细描述/原因/解决方案的行**照常导入**，弹窗提醒导入后请补填
  3. **未识别列提醒（v1.8.4）**——文件中未能识别为标准列名的列以琥珀色提示：已按自定义扩展字段处理；若为标准列名拼写有误（如误写「作业日期」应为「日期」），请修正文件后重新导入。模板自带的"自定义列示例"列不触发提醒
- **导入结果通知**：导入完成后通知汇总成功导入 / 重复跳过 / 缺经验字段 / 未识别列条数；存在提醒项时以警告样式展示明细（重复明细、写入失败行、缺字段行）
- **登记日期**：导入文件含「登记日期」列时按文件值录入；无该列时自动取导入当天日期，补录历史数据无需手工补列
- **导出**：按当前筛选+排序导出，状态列自动着色（红/黄/绿/灰），跨项目导出时附加"项目"列，末尾含"登记日期"列（记录录入系统的时间）

**问题** 与 **解决方案** 两列固定宽度（保证各记录间宽度一致、表格不被长文本挤压）：内容超过约 2 行时默认折叠并显示省略号，**点击单元格即可展开/收起全文**（悬停可查看完整内容提示）；单元格右侧有 **复制按钮**，一键复制全文，方便粘贴到工单或报告。

### 25.8 AI 经验分析（可选功能）

> 需在服务端配置 OpenAI 兼容的 LLM 服务（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_CHAT_MODEL`，见 `.env.example`）；未配置时「AI 分析」入口自动隐藏，不影响其他功能。

在新增/编辑台账弹窗中填写 **问题**（至少 4 个字）后，点击「AI 分析」：

1. **相似案例召回**：系统从已闭环（已完成/已关闭）的历史台账中检索相似案例，优先同项目、同系统、近期记录，并按关键词跨项目/跨时间扩展召回
2. **流式生成**：分析结论以打字机效果逐段输出（原因分析按可能性排序并标注置信度、建议排查步骤、风险提示），等待时间显著缩短
3. **相似案例列表**：展示每个案例的匹配度百分比与摘要，**点击案例可直接打开对应台账详情**（无编辑权限则以只读模式打开），参考历史处理方式
4. **自动降级**：若流式服务异常，自动回退为一次性生成；若未召回任何相似案例，直接给出常规排查建议，不消耗模型调用

**语义召回（可选增强）**：服务端配置 `LLM_EMBED_MODEL` 后，召回结果会叠加向量相似度重排——即使历史案例用词不同（如"登录卡顿" vs "认证延迟高"），语义相近的经验也会被召回。向量化结果按台账缓存，内容修改、删除或更换模型后自动重新计算；embedding 服务异常时静默退回关键词排序。

### 25.9 AI 排障助手（可选功能）

> 与 25.8 共用同一套 LLM 配置；未配置时工具栏「AI 助手」入口自动隐藏。

台账页工具栏点击「**AI 助手**」，右侧滑出对话面板：

1. **提问**：用自然语言描述问题（如"ERP 报销单无法提交，如何排查？"），按 `Enter` 发送、`Shift+Enter` 换行；空态时可直接点击示例问题
2. **检索与回答**：每轮自动检索台账相似案例（优先当前项目）后流式输出排查建议，回答中引用的案例编号可溯源
3. **参考案例**：回答下方列出本轮召回的案例（匹配度百分比），**点击即打开对应台账详情**（强制只读查看，不可修改；跨项目案例无查看权限时会提示"该案例所在项目不在你的可见范围内"）
4. **多轮追问**：支持连续对话补充上下文（如"账号没锁，还是报 500"），服务端结合最近两轮输入优化召回
5. **停止生成**：流式输出中可点击停止按钮中止，已生成的部分保留

**说明**：对话历史仅保存在当前页面（刷新即清空，服务端不落库）；台账中没有相关案例时，助手会先如实说明，再给出通用排查建议并标注，不编造台账依据。
